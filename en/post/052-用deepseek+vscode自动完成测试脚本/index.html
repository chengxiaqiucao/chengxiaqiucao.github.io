Generating Test Scripts Automatically with DeepSeek and VS Code

Using DeepSeek inside VS Code to generate test scripts.

Jan 31, 2025
23 minute read
中文

DeepSeek has been all the rage in recent days, so I gave it a try myself, and it is indeed very powerful. The AI ToolKit extension for VS Code has also integrated the DeepSeek R1 model by now, so here I would like to share my hands-on experience of using DeepSeek inside VS Code to help us complete automated test scripts.

Installing AI ToolKit and Enabling DeepSeek

Microsoft officially provides an AI-assistance extension, namely AI ToolKit for Visual Studio Code. This extension can leverage a variety of open-source or commercial large language models, and it has now integrated the DeepSeek R1 model, allowing us to conveniently use DeepSeek within VS Code to assist with our code development.

First, find AI ToolKit in the extension marketplace and complete the installation.

Once the extension is installed, on its page select the Models page in the Catalog, and use the DeepSeek-R1 model by applying the filters hosted by Github and publisher Deepseek.

AI-Assisted Script Generation

With the DeepSeek model available, we can create a new playground and let DeepSeek generate automation scripts for us. Below are the test scripts targeting saucedemo that I had DeepSeek generate.

@pytest.mark.parametrize("user_key, expected_success, expected_error", [
    ("valid_user", True, None),

])
def test_login(login_page, users, user_key, expected_success, expected_error):
    user = users[user_key]
    login_page.login(user['username'], user['password'])

        assert login_page.page.url == "https://www.saucedemo.com/inventory.html"
    else:
        assert login_page.get_error_message() == expected_error

Key Points and Explanation

  1. POM Design Pattern:

    • Each page (such as the login page or the inventory page) is encapsulated as a class, with page elements and operations abstracted into methods, thereby improving code reusability and maintainability.

  2. Data-Driven Testing:

    • User data is separated from the test code and stored in a YAML file, which improves maintainability and makes it easy to add new test scenarios.

  3. Exceptional Scenario Coverage:

    • Parametrized tests verify whether different erroneous inputs (such as a locked user, a wrong password, or a missing required field) trigger the correct error prompt.

  4. Fixture Management:

    • pytest fixtures are used to manage the browser and page objects, ensuring the independence of each test case and reducing duplicate code.

  5. Playwright Auto-Waiting Mechanism:

    • Playwright’s built-in auto-waiting ensures that elements are in an interactable state before being operated on, enhancing test stability.

This solution covers both normal and exceptional business flows, ensuring automated verification of the core functional points (login, cart, checkout) and improving software quality.

Conclusion

Referring to the results given, they can be executed successfully with almost no fine-tuning, which indeed greatly improves our efficiency in automation implementation. What is most valuable is that the thinking process provided by DeepSeek is also of great reference value for the key points of our code implementation and test case design!

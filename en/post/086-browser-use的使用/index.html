Browser Use - A Detailed Guide to the AI-Powered Browser Tool

Apr 30, 2025
7 minute read
中文

Foreword

In several of our previous articles on AI testing, we introduced methods for achieving AI-driven test automation through several different AI browser tools, including playwright-mcp, midscene.js, and magentic ui. In fact, before these constantly emerging new tools appeared, there was an AI browser-driving tool that was released even earlier (2024.11) and is likewise still being continuously refined: Browser Use. Its implementation approach provided a great deal of reference for the related tools that came later. And after more than half a year and over 40 version iterations, the current latest version is 0.2.5, and the tool’s features have become increasingly complete.

In this article, let us take a systematic look at this AI browser.

browser-use Overview

browser-use is positioned as a simple yet powerful solution that connects different AI Agents with browsers, enabling AI-based intelligent browser automation.

It is a Python-based open-source library with over 61K stars on GitHub, which shows just how much attention it has attracted.

It mainly relies on the browser-control capabilities of Playwright/Puppeteer and the reasoning and analysis capabilities of large AI models to accomplish the shift of AI from an information assistant to an assistant that helps with execution. After it, MCP became widespread, and the subsequent variety of other AI-driven browser approaches all bear traces of the browser-use solution.

How It Works

The implementation of browser-use is, in fact, an AI Agent built with Langchain and LLM (Large Language Model) that understands web page content and further generates operation instructions. At its core, the project relies on the Playwright framework to implement browser automation operations, supports multiple browsers (such as Chromium, Firefox, etc.), and can simulate real-user behaviors like clicking, typing, and navigation.

Based on AI capabilities, the system can automatically identify interactive elements on web pages (such as buttons, input fields, etc.) and, combined with an understanding of the context, generate the corresponding interaction logic, improving automation efficiency and achieving AI-based browser intelligence.

Core Architecture Analysis

browser-use achieves deep integration between the AI Agent and the browser through a layered architecture. The main roles of the different layers of its core architecture are as follows:

Agent Layer (Decision Center)

This layer is mainly responsible for task-flow orchestration and decision-making. It manages the task flow by implementing a small state machine and interacts with the LLM (such as OpenAI) to obtain decision instructions.

Controller Layer (Instruction Converter)

This layer is responsible for translating high-level decisions into concrete browser operation instructions, supporting basic actions such as DOM operations and page navigation, and also providing management of multi-tab interaction logic.

DOM Parsing Engine

This layer performs real-time parsing of web page structure and content, including providing visual recognition capabilities (OCR support), and completes the construction of the mapping relationships for operable web page elements.

Browser Interface Layer

At this layer, the browser behavior is actually driven based on the Playwright framework. In addition to the built-in headless mode control, it can also interact with the user’s browser by specifying a browser path.

from langchain_deepseek import ChatDeepSeek
from browser_use import Agent
from pydantic import SecretStr, BaseModel, ValidationError, field_validator, ConfigDict, Field
from dotenv import load_dotenv
import os
import asyncio
from typing import List,Optional
from browser_use import Controller
import json


# Unified model output definition
class PostItem(BaseModel):
    model_config = ConfigDict(extra="ignore")
    
    post_title: str  
    post_url: str
    num_comments: int
    hours_since_post: int
    
    @field_validator('num_comments', 'hours_since_post', mode='before')
    def convert_numbers(cls, value):
        """Ensure numeric fields are converted to integers"""
        if isinstance(value, str) and value.isdigit():
            return int(value)
        return value or 0  

class Posts(BaseModel):
    posts: list[PostItem]
    total: int

# Result parsing function
def parse_result(result: str | dict) -> Posts:
    """Safely parse result data"""
    try:
        if isinstance(result, str):
            data = json.loads(result)
        else:
            data = result
            
        print("Parsed data:", data)
        return Posts.model_validate(data)
        
    except (json.JSONDecodeError, ValidationError) as e:
        print(f"解析错误: {type(e).__name__}: {e}")
        # Non-JSON format, return the result directly
        return result

controller = Controller(output_model=Posts)

load_dotenv()
api_key = os.getenv("DEEPSEEK_API_KEY")

# Initialize the model
llm=ChatDeepSeek(base_url='https://api.deepseek.com/v1', model='deepseek-reasoner', api_key=SecretStr(api_key))

async def main():
    # Create agent with the model
    agent = Agent(
        task="测试saucedemo.com网站standard_user的登录功能, 使用不同密码(secret_sauce,空密码)，登录成功则验证完成，否则需要输出错误信息。测试结果需要包含以下信息：\n1. 登录是否成功\n2. 如果登录失败，错误信息是什么\n",
        llm=llm,
        use_vision=False
    )
    history  = await agent.run()
    result = history.final_result()
    parsed = parse_result(result)
    
    if parsed.posts:
        for post in parsed.posts:
            print('\n--------------------------------')
            print(f'Title:            {post.post_title}')
            print(f'URL:              {post.post_url}')
            print(f'Comments:         {post.num_comments}')
            print(f'Hours since post: {post.hours_since_post}')
    else:
        print(result)

# Async main function
if __name__ == "__main__":
    try:
        asyncio.run(main())
    except Exception as e:
        print(f"程序运行时出错: {e}")

From the output above, we can see that Browser-Use decomposed the task into 6 steps:

  1. Start the task and visit the website https://www.saucedemo.com
  2. Enter the normal user standard_user/secret_sauce and click the login button

  4. Log out after clicking the menu
  5. Log in again with an empty password
  6. Complete the test and obtain the output result

Summary

Through the case above, we can see that Browser-Use can effectively leverage the LLM, based on the prompt we input, to decompose tasks, achieve effective parsing of the page, complete execution, and obtain results.

In terms of execution efficiency, API calls are relatively slow, and complex tasks take a long time. Moreover, once the task has started, we cannot intervene in the subsequent execution path (unless we force an interruption), which is also a key optimization direction for later tools such as Magentic UI.

But the advantage of Browser-Use is that it is already fairly mature, has good support for both local large models and a variety of online large models, has abundant community practice, and there is already considerable practice in using it to assist with test automation, including the optimization of system prompts. It is a good direction for us to leverage AI-assisted test automation.

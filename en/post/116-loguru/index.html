A New Way to Log in Python - Using the Loguru Library

Introducing a Python logging library

Jul 31, 2025
13 minute read
中文

Introduction

Anyone who has developed Python programs or written automation scripts in Python knows how important logging is to a program. Python has a built-in standard library for logging, logging, but this library is relatively complicated to use.

In this article we introduce a currently very popular third-party logging framework, Loguru, which has over 22K stars on GitHub. It is a more intuitive and easier-to-use alternative to logging. Developers can focus on business logic instead of the tedious details of logging configuration.

Using Loguru

1. Installation and Quick Start

1

pip install loguru

The simplest way to use it:

from loguru import logger

# filtering by level
def level_filter(level):
    def is_level(record):
        return record["level"].name == level
    return is_level

logger.add(sys.stderr, filter=level_filter(level="WARNING"))

# filtering by module
logger.add("app.log", filter="my_module")  # only log from my_module
logger.add("error.log", filter=lambda record: record["level"].no >= 40)  # only errors and above

Using loguru in pytest - Problems and Solutions

Introduction

In the previous article, we recommended a third-party Python logging library, loguru, which is very simple to use and fully featured. See that article 【】

But for those of us doing test automation who often use the pytest framework, there is a small problem. The built-in log capture mechanism of Pytest is optimized on top of the standard library logging. So when we use the pytest framework, if pytest’s own logging mechanism is involved - that is, pytest’s built-in fixture caplog actually still uses the standard logging module - the logs defined by the loguru library are difficult to take effect.

Of course, the problem is not big. In this article we briefly discuss this problem and introduce a compatibility solution.

caplog in Pytest

First let’s introduce Pytest’s logging.

caplog is a built-in fixture provided by pytest for capturing and testing log output.

Because of this built-in plugin, when we run pytest tests, by default standard output and log information recorded by the logging module are only shown when a test case fails.

Naturally this means we cannot use some APIs provided by caplog such as caplog.text, caplog.records, which creates some obstacles for us to make flexible use of pytest.

Solving the Compatibility Problem

There are multiple solutions to this compatibility problem; here I share what I verified.

Solution 1: pytest-loguru

When a problem exists, of course we can first check whether the community has an existing solution, and we find that someone has already provided one. It is the pytest-loguru plugin.

Just install it with the following command:

pip install pytest-loguru

But in my actual test, I found it reports a handle error on Windows systems.

So here I recommend using solution two.

# conftest.py
import pytest  
import logging  
from loguru import logger  
  
  
class SafePropagateHandler(logging.Handler):  
    def __init__(self):  
        super().__init__()  
        # ensure there is a basic formatter  
        self.setFormatter(logging.Formatter('%(levelname)s - %(message)s'))  
  
    def emit(self, record):  
        try:  
            # get the standard logging logger  
            std_logger = logging.getLogger(record.name)  
  
            # ensure the logger has a handler  
            if not std_logger.handlers:  
                # add a null handler to avoid "No handlers" warning  
                std_logger.addHandler(logging.NullHandler())  
  
            # handle the record safely  
            std_logger.handle(record)  
        except Exception:  
            # if propagation fails, ignore silently to avoid affecting the test  
            pass  
  
  
@pytest.fixture(scope="session", autouse=True)  
def setup_safe_loguru_integration():  
    # remove Loguru's default handler  
    logger.remove()  
  
    safe_handler = SafePropagateHandler()  
  
    # add the propagation handler to Loguru  
    handler_id = logger.add(  
        safe_handler,  
        format="{message}",  # simplify format to avoid duplication  
        level="DEBUG",  
        backtrace=False,  
        diagnose=False,  
        catch=True  # catch exceptions in the handler  
    )  
  
    # configure standard logging to avoid conflicts  
    logging.basicConfig(  
        level=logging.INFO,  
        format='%(levelname)s - %(message)s',  
        handlers=[logging.NullHandler()]  
    )  
  
    yield  
  
    # cleanup  
    logger.remove(handler_id)

Running again, we can see that caplog can now correctly capture logs recorded by loguru.

More on Python’s logging library loguru - A Full Comparison with the Standard Library logging

In earlier articles, we recommended Python’s third-party logging library loguru, mainly introducing loguru’s basic usage. In this article we compare it in detail with the standard library logging from multiple angles, to understand its advantages more intuitively.

import logging

# standard logging requires multiple configuration steps
logger = logging.getLogger(__name__)
logger.setLevel(logging.DEBUG)

# create a console handler
console_handler = logging.StreamHandler()
console_handler.setLevel(logging.INFO)

# create a file handler
file_handler = logging.FileHandler('app.log')
file_handler.setLevel(logging.DEBUG)

# create formatters
console_formatter = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')
file_formatter = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(filename)s:%(lineno)d - %(message)s')

# set the formatters
console_handler.setFormatter(console_formatter)
file_handler.setFormatter(file_formatter)

# add the handlers
logger.addHandler(console_handler)
logger.addHandler(file_handler)

# only now can we start using it
logger.info("Configuration complete, start logging")

Loguru’s configuration:

1
2
3
4
5
6
7

from loguru import logger

# Loguru accomplishes the same thing in one line
logger.add(sys.stdout, level="INFO", format="{time} - {name} - {level} - {message}")
logger.add("app.log", level="DEBUG", format="{time} - {name} - {level} - {file}:{line} - {message}")

logger.info("Configuration complete, start logging")

Advantage comparison:

  • Standard logging: Needs multiple objects such as logger, handler, formatter to be created and configured in multiple layers
  • Loguru: All configuration is done through a simple add() method, reducing code by more than 70%

import time
import logging
from loguru import logger

# test standard logging performance
def test_standard_logging():
    std_logger = logging.getLogger('test')
    std_logger.setLevel(logging.DEBUG)
    handler = logging.StreamHandler()
    handler.setLevel(logging.DEBUG)
    std_logger.addHandler(handler)
    
    start = time.time()
    for i in range(10000):
        std_logger.debug(f"Test message {i}")
    end = time.time()
    return end - start

# test Loguru performance
def test_loguru():
    logger.remove()
    handler_id = logger.add(sys.stderr, level="DEBUG")
    
    start = time.time()
    for i in range(10000):
        logger.debug(f"Test message {i}")
    end = time.time()
    
    logger.remove(handler_id)
    return end - start

Performance comparison results:

  • Standard logging: Slightly better performance in simple scenarios, but limited features
  • Loguru: Performance close to standard logging when advanced features (such as async, formatting) are enabled, but more powerful

Memory usage comparison:

  • Standard logging: Each logger instance uses more memory
  • Loguru: Singleton pattern, more efficient memory usage

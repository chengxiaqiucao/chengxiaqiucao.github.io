阅读时长: 4 分钟

几周前，一家做企业软件的小团队遇到一个新瓶颈：手工验证。写代码变快了，测试这边跟不上。当时的判断是，测试要跟上越来越多的改动，唯一的办法是把 AI 引进来；具体做法是用风险评估决定哪些活完全交给机器、哪些留给人。当时答应回头汇报，下面就是后续。

先看压力是怎么来的。三件事同时发生，全砸在测试头上。

图 1｜产能涨、代码涨，人手却在收缩

活变多了

用 Jira 和 GitHub 的数据画了一张图。活跃开发者的定义是一个月合并超过五个 PR。

数字有点噪声，因为工单的写法变了：过去大多由产品负责人手写，后来用 ChatGPT 润色，现在人人都在用 Claude 加 Jira MCP：Claude 写第一版，人来检查和修改。

趋势很清楚。三年里，同样六七个人的团队，交付量大致持平。一月把工具从 Cursor 换成 Claude 之后，2026 年同一个团队每月完成的工单比 2025 年多了约 44%（不算缺陷），每月合并的 PR 大致翻倍。从五月起，每个工单携带的代码量约是过去的三倍：工单变大了，单个工单里塞进的功能多了。

人变少了

同一时期，测试团队从 2.5 人缩到 2 人：其中一位测试工程师有一半时间在做别的岗位。活涨、人降，手工验证的口子就是这么撕开的。

到达测试之前的评审变少了

数据同样有噪声。2024 年 12 月为什么突然跳了一下，现在已经记不清了，但趋势清楚。2025 年，约四分之一的 PR 在没有其他开发者评审的情况下被合并。2026 年，这个比例到了一半，评审只由提交者自己借助 AI 完成。

由于代码评审不得不适应开发速度，测试因此成了主要的人工检查环节。即然提交者自己就能合并，到测试手里的东西就更需要有人兜底。活更多、人更少、到手之前评审更少。如果还坚持大部分靠手工测，结果不难想象。

图 2｜agent 管执行，人守着最终裁决

搭了什么

这套东西由一位叫 Javier 的测试工程师用 Claude Code 搭起来。春天还只是一个技能，后来长成了一整套测试工具箱，布署进了日常流程。几个原则撑起了这套流程。

每天从排好序的队列开始。早上第一件事，测试工程师启动一次扫描：一个 agent 走查每个待做工单，梳理每处改动碰到了哪些地方，跑已有测试，然后把队列排好序。

接下来由人决定测什么。agent 会提议这一轮怎么花时间：一组碰到同一块产品的工单、风险最高的那个，或者几个能快速拿下的。提议归提议，选哪一组由人定。

先拿最便宜的证据。agent 把验收标准拆成小断言，每个用能判定它的最省事的方式去查：一个已有的测试，或者直接看代码。剩下的才送到浏览器里。

对着断言反着来

一个被要求验证工作的 AI，倾向于确认工作本身，因为需求和代码用的是同一批词。所以针对每个断言，agent 必须说出什么能证明它是错的。然后去看没人盯的地方：空值、最大值、两个开关同时打开、流程走到一半刷新。

结论留给人。测试工程师复核查了什么，回答 agent 提出的问题，要求补测更多场景。最终判断留在人这里，即便所有检查都通过。agent 永远不能把工单推进到 Done，未经允许也不能提缺陷单。

那块看板本地运行，也是用一个 Claude 技能搭的，是测试工程师管理测试的唯一入口：查过的场景、证据（视频和截图）、agent 的问题、要求补测的请求都在上面。上面那句话最贴切：“结论是你的，永远不会替你填。”

按团队自己的估算，agent 现在承担了一个工单上约 75% 到 85% 的动手执行，每张工单跑 16 到 29 个场景，测试工程师回答大约五个问题。这是一周会话的估算，不是精确测量。

没发生的事

低风险工单的完全自动化还没实现。原因有两个：一是测试团队不愿意完全放手，团队仍想看到查了什么，不想彻底外包给 AI、和产品失去接触；二是这事优先级不高，当前分类器很少把工单标成低风险，能外包的本来就不多。

现在的状态是：测试团队跟上了验证的浪头，但很勉强。左移（shift-left）的需求测试已经放弃，没时间做。团队忙，而且比主动更偏被动。工单处理不及时，队列就开始失控。

九月十月发现并修掉的缺陷数量猛增。一部分是新这套东西找出来的，一部分可能是夏天那些评审变少的代码带进来的；两者怎么分，目前还不清楚。这套做法很难长期持续，因为 AI 越好、工程侧的 harness 越强，工程产出还会继续加速。

下一步押在哪

几个可能的方向。测试这边可以让多个 agent 并行跑，人不停切换、不停做决定。也可以把测试做成一门 quality-harness engineering：设计上下文、工具和 agent 的交互方式，在安全的地方把人从循环里拿掉。还有一个是加州的风险投资商不再替小企业补贴 AI 订阅，大家回去手写代码。

押注落在第二个方向。瓶颈一直在移动，这一次穿过去的办法不是多招测试，而是把现有这些人周围的系统做扎实。
